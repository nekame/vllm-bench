# Компиляция, ACL Graph и eager при профилировании Pangu 505B

Документ фиксирует обсуждённое поведение для целевого интерфейса vLLM 0.25.1 и OmniInfer `4cd855b29b5eb0a78bca645fad39e3181c35d099`. Проверялись исходники; NPU-запуски на этой машине не выполнялись. Эффективный режим конкретного сервера нужно сверять с его логами и итоговой конфигурацией.

## Компиляция и replay графа — разные механизмы

Компиляция через `torch.compile` преобразует вычисления модели; её backend и passes могут менять разбиение и fusion. ACL Graph записывает последовательность device-задач и затем воспроизводит её, сокращая накладные расходы запуска. В vLLM название настройки остаётся `cudagraph_mode`, хотя OmniInfer использует NPU ACL Graph.

| Режим | Компиляция модели | Replay device-графов |
| --- | --- | --- |
| Целевой рабочий режим | По эффективной конфигурации | По конфигурации и поддержке текущего batch |
| Компиляция с `cudagraph_mode=NONE` | Может оставаться включённой | Отключён |
| `--enforce-eager` | Отключается средствами vLLM | Отключён |

Готовые NPU kernels и fused operators продолжают использоваться и в eager. Отключение компиляции модели не превращает их в элементарные Python-операции и не отключает автоматически все аппаратные оптимизации.

## Всегда ли prefill выполняется в eager

Нет. Нельзя делать универсальный вывод «prefill — eager, decode — graph». В зависимости от backend, конфигурации и формы batch prefill может выполняться без device-графа либо с графами отдельных участков или полным графом, если выбранный путь это поддерживает.

В [NPUModelRunner](https://gitee.com/huting233/omniinfer/blob/4cd855b29b5eb0a78bca645fad39e3181c35d099/omni/worker/npu_model_runner.py#L450) режим выбирается для batch: учитываются число токенов, признак uniform decode, ограничения и доступные графы. Это не обещание поддержки всех вариантов для любой модели.

Отсутствие полного графа не доказывает чистый eager: вычисления могут оставаться скомпилированными, а отдельные участки — выполняться через piecewise-графы. Количество prefill chunks также не определяет режим компиляции. `--max-num-batched-tokens` регулирует token budget планировщика, хотя изменение формы batch может косвенно повлиять на выбор графа.

## Почему метки слоёв могут быть только на prefill

Наш [sitecustomize.py](./instrumentation/sitecustomize.py) оборачивает Python-методы слоёв `forward` и `mhc_head` в `torch.autograd.profiler.record_function`. Метки `pangu12/layer_…` показывают CPU-диапазоны вызовов Python, а не длительность NPU-вычислений слоя.

Если prefill вызывает эти обёртки, метки появляются. При replay записанного графа Python-код слоёв повторно не выполняется: [ACLGraphWrapper вызывает `entry.aclgraph.replay()`](https://gitee.com/huting233/omniinfer/blob/4cd855b29b5eb0a78bca645fad39e3181c35d099/omni/compilation/acl_graph.py#L387). NPU выполняет вычисления, но наши Python-метки заново не создаются. Компиляция также может менять их видимость.

Следовательно, наличие меток не доказывает полностью eager-исполнение prefill, а отсутствие меток не доказывает потерю decode из трассы. Для рабочего режима нужно смотреть NPU kernels и границы replay. Текущий `--annotate-layers` не реализует device-метки слоёв, воспроизводимые внутри графа.

## Что делает `--enforce-eager`

В [VllmConfig v0.25.1](https://github.com/vllm-project/vllm/blob/v0.25.1/vllm/config/vllm.py#L1022) этот флаг принудительно выставляет:

```text
compilation_config.mode = CompilationMode.NONE
compilation_config.cudagraph_mode = CUDAGraphMode.NONE
```

Поэтому добавление `--enforce-eager` не сохраняет явно запрошенную компиляцию модели. Характерное сообщение в логе: `Enforce eager set, disabling torch.compile and CUDAGraphs.`

Кроме того, OmniInfer [выводит `task_config.graph_mode` из `model_config.enforce_eager`](https://gitee.com/huting233/omniinfer/blob/4cd855b29b5eb0a78bca645fad39e3181c35d099/omni/model_config/config_loader/loader.py#L54). При eager его [apply_eager_mode_config](https://gitee.com/huting233/omniinfer/blob/4cd855b29b5eb0a78bca645fad39e3181c35d099/omni/model_config/config_loader/features.py#L15) также отключает ряд оптимизаций: attention/mHC multistream, mHC fusion, super-kernel и prefetch. Это дополнительная причина различий с рабочим графовым режимом. Все коммуникации и все streams этот флаг не отключает.

Для отдельного диагностического сервера добавьте к своей обычной команде `serve.py`:

```bash
--annotate-layers --enforce-eager
```

Наш [serve.py](./serve.py) передаёт `--enforce-eager` в vLLM. Для фактического запуска по-прежнему нужен `--execute`. Изменение режима требует перезапуска сервера; запускать заново подготовку checkpoint не требуется.

В eager Python-метки должны быть видны при вызове обёрнутых методов. Их накладные расходы входят в профиль. Времена eager-запуска нельзя переносить на рабочий graph mode.

## Как оставить компиляцию, отключив графы

Не передавайте `--enforce-eager`. В существующий `--compilation-config` добавьте или измените поле:

```json
"cudagraph_mode": "NONE"
```

Сохраните свой `mode`, backend и остальные параметры компиляции. Само поле `cudagraph_mode=NONE` не включает компиляцию, если она уже отключена другим параметром или переменной окружения.

Для передачи через наш launcher используется `--engine-cli-json`. Например, файл дополнительной аргументации может содержать:

```json
[
  "--compilation-config",
  "{\"cudagraph_mode\":\"NONE\"}"
]
```

Это минимальный пример отключения графов, а не замена вашей полной конфигурации компиляции. Если `--compilation-config` уже есть в массиве, измените его JSON вместо добавления второго аргумента. Передайте файл обычной команде `serve.py` через `--engine-cli-json /path/to/engine-cli.json`.

Проверьте итоговые `mode`, backend и `cudagraph_mode` в логе сервера: исходные CLI-параметры могут переопределяться платформой или другими настройками. В этом варианте Python-аннотации также не гарантированы, поскольку компиляция остаётся отдельным фактором.

## Как сравнивать профили

Для оценки целевого TPOT используйте рабочую компиляцию, графы и настройки streams. Для разбора Python-структуры слоёв используйте отдельный eager-запуск с аннотациями. Промежуточный запуск с компиляцией и `cudagraph_mode=NONE` помогает отделить влияние replay от компиляции, но eager OmniInfer меняет и дополнительные оптимизации, поэтому разницу времён нельзя целиком приписывать одному механизму.

При сравнении сохраняйте checkpoint, TP/DP/EP, operator config, входные токены, длину генерации, concurrency и прогрев. Серверный manifest содержит исходную команду, но не заменяет лог итоговой конфигурации.
